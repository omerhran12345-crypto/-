# SIMS — Smart Inventory Management System

مشروع واجهة SIMS مستقل عن Base44 وNetlify ومنصات البناء المغلقة. يمكن نشر الواجهة الثابتة على GitHub Pages، بينما تتطلب الحسابات والبيانات المشتركة إعداد Supabase.

## ما الموجود في هذه النسخة؟

- واجهة عربية RTL متجاوبة للكمبيوتر والهاتف، ومظهر نهاري/ليلي.
- لوحة معلومات ومؤشرات محسوبة من بيانات المنتجات والفواتير.
- إدارة المنتجات: إضافة، تعديل، أرشفة، بحث، فلترة، تحديد متعدد.
- استيراد Excel/CSV وتصدير Excel.
- نقطة بيع محلية مع التحقق من عدم بيع كمية أكبر من الرصيد، وتحديث المخزون عند إتمام الفاتورة. في الوضع السحابي تتم عملية البيع داخل دالة SQL واحدة للتحقق من الرصيد وتحديثه وتسجيل الفاتورة.
- سجل فواتير وطباعة.
- تنبيهات محسوبة للمخزون المنخفض والصلاحية.
- صفحات أولية لبوابة الطبيب والمواطن، مع توضيح أنها غير مفعلة طبياً/وطنياً.
- تكامل اختياري مع Supabase للمصادقة وتخزين المنتجات، مع ملف SQL أولي.

**مهم:** عند عدم ضبط Supabase يعمل التطبيق في وضع محلي على المتصفح نفسه. هذا الوضع ليس قاعدة بيانات مشتركة ولا نظاماً آمناً متعدد المستخدمين. بيانات المبيعات المحلية تحفظ في المتصفح؛ أما البيع السحابي يستخدم دالة SQL ذرية لتحديث المخزون وتسجيل البيع.

## التشغيل محلياً

يتطلب Node.js 20 أو أحدث.

```bash
npm install
npm run dev
```

## رفع المشروع إلى GitHub

1. أنشئ مستودعاً جديداً على GitHub.
2. فك ضغط ملف ZIP وارفع محتوياته إلى جذر المستودع، بحيث يظهر `package.json` في المستوى الأعلى.
3. من تبويب **Actions** أو **Settings → Pages** يمكنك تفعيل النشر الثابت. إعداد GitHub Actions موجود في `.github/workflows/deploy.yml`.
4. سيُبنى التطبيق باستخدام `npm ci` و`npm run build` ثم يُنشر مجاناً على GitHub Pages.

## إنشاء Supabase وربطه بـ GitHub Pages

1. أنشئ مشروعاً جديداً من [Supabase](https://supabase.com/dashboard) واحفظ Project URL ومفتاح Publishable/anon في مكان آمن.
2. افتح **SQL Editor → New query** والصق محتوى `supabase/schema.sql` وشغّله على المشروع الجديد. لا تشغّله عشوائياً فوق قاعدة بيانات تحتوي بيانات مهمة؛ راجع المخطط أولاً وخذ نسخة احتياطية.
3. من إعدادات Supabase انسخ Project URL وPublishable/anon key.
4. في GitHub افتح **Settings → Secrets and variables → Actions → Variables** وأضف المتغيرين التاليين (هذه قيم عامة للواجهة وليست مفاتيح خادم سرية):
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
5. من **Settings → Pages** اختر النشر بواسطة **GitHub Actions**، ثم افتح **Actions** وشغّل سير العمل أو ادفع تحديثاً إلى الفرع `main`/`master`.
6. في Supabase Auth، اضبط Site URL وRedirect URLs على رابط GitHub Pages الخاص بمستودعك، وفعّل تأكيد البريد الإلكتروني إذا كنت تريد ذلك. جرّب التسجيل وتسجيل الدخول قبل إدخال بيانات حقيقية.

مفتاح Supabase القابل للنشر فقط هو المسموح في الواجهة مع سياسات RLS. **لا تضع `service_role` أو مفتاح OpenAI السري في GitHub Pages أو أي متغير يبدأ بـ `VITE_`.** مفاتيح الذكاء الاصطناعي تحتاج خادماً خلفياً منفصلاً.

## حدود النسخة الحالية — اقرأ قبل الاستخدام الحقيقي

هذه نسخة أولية قابلة للتطوير وليست بعدُ نظاماً صيدلانياً وطنياً مكتملاً. لم يمكن التحقق من نجاح البناء في بيئة التطوير الحالية بسبب تعذر الوصول إلى سجل حزم npm؛ يجب التأكد من نجاح GitHub Actions قبل اعتبار النشر ناجحاً. لا تتضمن حالياً: OTP مخصصاً من 8 أرقام، صلاحيات قطاعات/مؤسسات كاملة، إشعارات بريدية فعلية، OCR للفواتير بالصور، بحث خرائط حقيقي، مساعد ذكاء اصطناعي متصل بمصدر موثوق، تنبؤاً تم التحقق منه إحصائياً، تتبع دفعات FEFO، أو بوابات طبيب/مواطن إنتاجية. لا تعتبر صفحات البوابات الحالية خدمات فعالة. لا تخزن بيانات مرضى حقيقية ولا تعتمد عليها لاتخاذ قرارات علاجية. تعذر التحقق من بناء Vite في بيئة العمل الحالية لأن تثبيت npm انتهى بمهلة زمنية دون تنزيل الحزم. يضيف GitHub Actions خطوة تحقق من وجود `dist/index.html`، لكن لا يعني ذلك أن البناء نجح مسبقاً. يلزم نجاح سير العمل فعلياً، واختبارات تكامل وأمن ومراجعة SQL/RLS قبل نشر بيانات حقيقية.

## الملفات

- `src/App.jsx`: صفحات الواجهة والتفاعلات.
- `src/lib/db.js`: طبقة البيانات المحلية/السحابية.
- `src/styles.css`: التصميم المتجاوب والثيمات.
- `supabase/schema.sql`: مخطط أولي وسياسات أمان ودالة تسجيل بيع ذرية.
- `.github/workflows/deploy.yml`: نشر GitHub Pages.
